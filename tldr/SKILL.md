That last message was too long. Rewrite it so I can read it in seconds. Change the words, not the facts. If text is given here, rewrite that instead: $ARGUMENTS

**Layout**

1. Put the **Summary** section first in a tl;dr 
2. Then add only the sections that apply: **Terms**, **What was done**, **Not done**, **Problems and risks**, **Next Step**. 
3. Give results only. For the steps taken, what was checked, options rejected, and the reasons behind choices, if they are important and worth of user's attention, list them in the final section as Appendix. 
4. Every section must use bullets to list results
5. Each bullet is one point in one or two lines. Start it with a bold label naming what it is about.

**Simple English**

Write in ASD-STE100 Simplified Technical English: common words, one idea per sentence, under 20 words, active voice, simple tenses. No opener, no closer, no filler. No comparisons, analogies, or metaphors. 

**No invented terms**

Do not use words a normal dictionary does not have, or common words given a private new meaning. Say what the thing does in plain words instead. If a technical term comes up often and plain words cannot replace it or it would be too long, define it in one line under **Terms** before using it.
